# 中文翻译腔参考

本文件供项目内容去 AI 味 Skill 使用。它不是中文禁用词表，也不是自动判定翻译质量的规则。

## 先看结构

翻译腔是原文语言改变了目标语言的表达：意思大致正确，句子却不像目标语言作者直接写的。中文项目内容里常见的原因有：

- 英文后置修饰语被压成很长的中文前置定语；
- 英文被动句、形式主语、介词和连接词被逐项翻译；
- “进行、作出、予以、给予、实现”等空壳结构替代了实义动词；
- 为了贴近原文，保留了英文的语序、名词化和从句层次；
- AI 把正式、完整、对称误当成高质量，反复使用这些结构。

翻译腔和正式中文不是一回事。法律、学术、技术、政策文本可以正式，也可以使用被动、术语和长句。只有在这些形式没有必要、成簇出现，或把动作和关系藏起来时才改。

## 常见问题和改法

### 1. “的”字长链

英文关系从句或后置修饰语被全部压到一个名词前。

```text
翻译腔：这是一个由多个团队共同维护的、能够处理多语言输入的、面向企业客户的系统。
自然：这是一个面向企业客户的多语言系统，由多个团队共同维护。
更自然：这套系统面向企业客户，支持多语言输入，由多个团队共同维护。
```

拆句、调整信息顺序，或把修饰关系改成独立事实。不要为了减少“的”而删掉事实。

### 2. 英文被动句

```text
翻译腔：该功能被用户广泛使用，并被认为是产品的重要组成部分。
自然：用户广泛使用这个功能，团队把它视为产品的重要组成部分。
```

能找到行动者且行动者相关时，优先改主动。行动者未知、需要保护、与当前重点无关，或文体要求突出受事时，保留被动。不要把所有“被”都改掉；新闻、法律、事故报告和学术文本有时确实需要被动。

### 3. “被……所……”和“为……所……”

这类结构经常是英文 passive + by 的硬翻译：

```text
翻译腔：该方案为团队所采用。
自然：团队采用了这套方案。
```

只有在强调对象、行动者不明，或正式文体需要时保留。

### 4. 空壳动词

| 翻译腔 | 优先检查 |
| --- | --- |
| 进行研究 | 研究 |
| 进行讨论 | 讨论 |
| 作出决定 | 决定 |
| 作出回应 | 回应 |
| 予以支持 | 支持 |
| 给予帮助 | 帮助 |
| 实施改进 | 改进 |
| 展开分析 | 分析 |
| 实现提升 | 提升、提高，或写具体结果 |
| 起到作用 | 直接说做了什么 |
| 提供保障 | 保障，或写具体保障措施 |

项目术语和固定搭配优先服从项目本身的约定。

### 5. 介词和框架词过量

检查这些词是否表达了真实关系：

- 作为……；
- 关于……、有关……；
- 对于……来说；
- 基于……；
- 围绕……展开；
- 通过……来；
- 在……方面；
- 从……角度来看；
- 在……背景下；
- 在……情况下。

```text
翻译腔：对于这个问题来说，我们将基于现有数据展开进一步的分析。
自然：我们会根据现有数据继续分析这个问题。
```

不要为了去翻译腔而删掉真实关系。`基于` 确实表达证据基础时可以保留，`在……方面` 需要限定范围时也可以保留。

### 6. 形式主语和“它”

英文的 `it`、`this`、`the system`、`the approach` 不一定要逐句译成“它”“这”或“该系统”。中文可以使用项目名称，也可以省略主语。

```text
翻译腔：该系统能够处理数据。它能够生成报告。它能够将报告导出为 PDF。
自然：这套系统能处理数据、生成报告，并导出 PDF。
```

不要删除确实承担指代作用的代词。

### 7. 连接词逐项翻译

英语常用显式连接词，中文有时靠语序和语境表达关系。检查“此外、与此同时、因此、然而、以及、从而、进而、同时”是否过密。

```text
翻译腔：此外，系统支持缓存。因此，用户可以更快地打开页面。与此同时，服务器的压力也会降低。
自然：系统支持缓存，页面打开更快，服务器压力也会降低。
```

因果、转折、条件确实需要明确标出时，保留连接词。

### 8. 目的和结果外壳

```text
翻译腔：我们进行了重构，以便使系统得以实现更高的性能，从而能够为用户提供更好的体验。
自然：我们重构了这部分代码，页面加载更快了。
```

先说动作，再说结果。不要堆叠“以便、使得、得以、从而、能够、提供”。

### 9. 条件和时间结构

```text
翻译腔：如果用户在登录页面进行操作的话，系统将会进行验证。
自然：用户登录时，系统会验证账号。
```

“如果……的话”“当……的时候”“在……之后”不是永远错误。保留真实条件和时序，删掉多余的语气外壳。

### 10. 英语从句塞进一个中文长句

英文关系从句、分词短语和插入语很容易被压成一条逗号长句。

```text
翻译腔：这个由团队去年开发的、能够处理大规模数据并且已经在多个项目中得到验证的工具，可以帮助用户快速完成迁移。
自然：团队去年开发了这个迁移工具。它已经在多个项目中处理过大规模数据，用户可以用它快速完成迁移。
```

按事实、动作、结果拆分。不要为了让中文句号和原文一一对应而保留英文层次。

### 11. 抽象名词和英文搭配直译

检查这些搭配：

- 获得……的能力；
- 提供……的支持；
- 对……进行讨论；
- 实现……的提升；
- 具有……的特征；
- 展示了……；
- 反映了……；
- 对……产生影响。

恢复成直接动作：

```text
获得快速恢复的能力 → 能快速恢复
提供技术支持 → 支持技术问题，或写具体支持内容
对方案进行讨论 → 讨论方案
实现性能的提升 → 性能提高了，或给出具体指标
具有较高的稳定性 → 运行更稳定，或给出故障率和时间
```

不要为了简短而损失范围、责任或因果关系。

### 12. 术语和中英混排

翻译腔和中英混排经常一起出现，但不能把所有英文术语都翻译掉。

保留：

- API、CLI、HTTP、JSON 等常用技术名；
- 代码、字段名、命令和标识符；
- 官方产品名和项目名；
- 没有同样精确中文译法的术语；
- 用户或项目已经确立的术语。

改写或解释：

- 只是为了显得专业而插入的英文；
- 一段中文里突然出现的不必要英语短语；
- 英文术语和中文句法重复表达同一信息；
- 同一篇文档里术语大小写和中英文写法不统一。

首次出现时可以给必要术语一个简短中文解释，之后统一使用项目规定的写法。

## 改写流程

1. 读完整段落和上下文，不要只替换命中的词。
2. 列出事实、限制、责任关系和术语。
3. 先用中文说清楚这段真正要表达什么。
4. 暂时不看原句结构，重新组织中文。
5. 对照原文检查有没有遗漏事实、改变范围、改变确定性或改变责任归属。
6. 检查“的”字链、被动、空壳动词、框架词、连接词和逗号长句。
7. 保留必要的正式表达、技术术语、固定法律表达和引用。
8. 朗读。拗口时优先重写句子结构，不要只换同义词。
